# Agent delegation guidance

- Follow the repository-wide delegation policy in the root `AGENTS.md`.
- The primary agent should proactively involve the specialist defined here when a substantial task benefits from that expertise: `design` for visual direction and UX, `frontend` for UI implementation and accessibility, `backend` for APIs and external integrations, and `testing` for test strategy and coverage.
- Run independent specialist reviews in parallel. Keep narrow edits direct when delegation would not add meaningful value.
- When the primary agent assigns an implementation task, own that scoped task end-to-end: make the design/technical decisions from the brief and repository evidence, implement the change, and run relevant checks. Do not stop at recommendations unless the assignment explicitly asks for inspection-only review.
- For parallel implementation, keep scopes and files non-overlapping; report files changed, key decisions, checks run, and any remaining verification needed. The primary agent coordinates and integrates the work.
- Subagents should focus on their assigned scope; do not start further subagents unless explicitly asked and permitted.
